    Framing

    Triage is a routing decision made nine times before coffee

    A supervisor's morning job is not to read claims. It is to send each one to the right person before the first-contact deadline, and to spot the one that will turn into a lawsuit. The screen is built to answer "what next, and to whom" for each claim, with the model's reasoning one glance away.

    One priority order, with its reasons shown
    The rank combines severity, litigation risk and time to first contact. The top of each claim says in words why it sits where it does, so the order can be challenged instead of trusted blindly.
    Scores come with their drivers
    A "68% litigation risk" on its own invites guessing. Listing what raised and lowered it, like an attorney mentioned in the first report, lets the supervisor check it against the claim notes.
    Suggestions respect workload
    Suggested adjusters account for how many open claims each person has. If the supervisor overrides, an adjuster near capacity is flagged before the assignment, not after.
    Batch actions check the rules first
    Tradeoff: fast track only accepts claims that meet every rule: low severity, no injury, litigation under 5%, estimate under $2,000. Mixed selections are blocked with the reason, which is slower but prevents a bodily injury claim slipping into automation.
    Not colour alone
    Severity uses a label and a bar count, and due-soon contact uses a marker and bold text as well as red. The queue works from the keyboard with J, K, A and X.

    Built on tokens

    Density is a token change, not a new layout

    Every colour, radius and row padding comes from a small token set. The Compact toggle above changes one spacing token and hides the secondary line, which is how implementation teams could offer density per client without forking components.

    What I'd test next
    Whether supervisors agree with the rank on real mornings, how often they override the suggested adjuster and why, and whether batch fast-tracking changes how carefully each claim is read.
